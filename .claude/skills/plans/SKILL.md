# plans

プロジェクトの計画書を整理する。計画書の数が増えても、作業中のものを見つけやすくするためのスキル。判断は、計画書のチェックボックスと、ファイル名の日付だけで行う(Jira は見ない)。

## 操作

- `整理`: 終わっていて、月が今月より前の計画書を、`archive/<年-月>/` に移す

## 書式

```
/plans 整理
```

- 引数は無い。対象は、実行しているプロジェクト(作業ディレクトリの git リポジトリ。`git rev-parse --show-toplevel` で決める)
- 移す作業は、そのリポジトリの中で行う
- そのリポジトリに `docs/superpowers/plans/` が無いとき(ルートのリポジトリで実行した場合など)は、何もせずに、「ここには計画書の置き場所が無い。プロジェクトのディレクトリで実行してほしい」と報告する

## 置き場所

```
docs/superpowers/plans/                      作業中・今月の計画書(直下の .md)
docs/superpowers/plans/archive/<年-月>/      終わった、前の月以前の計画書
```

- `<年-月>` は、ファイル名の先頭の日付(`YYYY-MM-DD-...`)の、年と月
- `archive/` の中は、整理の対象にしない

## 「終わった」の判断

計画書の中のチェックボックス(`- [ ]` と `- [x]`)で決める。

- 1個以上あり、すべてが `- [x]`(または `- [X]`)であれば、終わった
- 1個でも `- [ ]` があれば、終わっていない
- チェックボックスが0個のときは、判断できないので、終わっていないものとして扱う

チェックボックスは、実装・スモークテスト・コミットまで済んだ時点で、Claude が `- [x]` に更新する決まり。更新を忘れた計画書は、直下に残る(誤って移ることは無い)。終わったあとに見つかった修正は、計画書を開き直さず、新しいタスクとして Jira に作り、別の作業として行う。

## 動き(整理)

1. **今月を決める**: `date +%Y-%m` で、実行した日の年月を得る
2. **集める**: `docs/superpowers/plans/` 直下の `.md` のうち、次の2つを、両方満たすものを、移す対象にする
   - ファイル名が `YYYY-MM-DD-` で始まり、その年月が、今月より前
   - 「終わった」の判断で、終わったもの
   - 名前が `YYYY-MM-DD-` で始まらないものは、触らず、ファイル名を報告する
   - 月が前でも、終わっていないものは、移さず、残った理由(未チェックの数)を報告する
3. **一覧を見せる**: 移すファイルと、移動先のパスを示す。移さないものは、理由を添えて、別に示す。対象が0件なら、「移すものは無い」と報告して、終わる
4. **確認を取る**: 一覧を見せたあと、了承をもらってから移す。了承が無ければ、何も動かさない
5. **移す**: `mkdir -p` で月のフォルダを作り、`git mv` で移す(履歴を保つため。`mv` は使わない)
   - 移動先に、同名のファイルがあるときは、そのファイルだけ、移さずに報告する
   - 削除はしない
6. **参照の確認**: 移したファイルの旧パスを、そのリポジトリの中で検索する(`docs/`、`CLAUDE.md`、`README` など。`archive/` の中と、`.claude/skills/` は除く)。参照が残っていれば、場所を報告する。直すのは、頼まれたときだけ
7. **報告**: 移したもの、移さなかったもの(理由つき)、参照の残りを、簡潔に示す。コミットは、頼まれたときだけ行う

## やらないこと

- 計画書の中身(チェックボックスを含む)を、書き換えない
- 終わっていない計画書を、移さない。月が変わっても、動かさない
- Jira の状態は、見ない
- コミット・push・マージは、頼まれたときだけ
- `.superpowers/` 以下(サブエージェント実行の作業用の記録)は、触らない

## 前提

- 計画書の置き場所が、`docs/superpowers/plans/`(`superpowers:writing-plans` の既定)であること
- 計画書のファイル名が、`YYYY-MM-DD-<名前>.md` であること
- 作業が終わった時点で、計画書のチェックボックスが更新されていること(更新は、計画書を使って作業する側の決まり)
