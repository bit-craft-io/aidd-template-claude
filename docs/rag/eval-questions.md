# RAG 評価用の質問集

`docs/` の知識を引く RAG の、やり方(文書の分け方・検索方式・埋め込みモデル)を決めるための物差し。②(最小の通し)で、やり方を変えながら、この質問集を回し、結果を比べる。

## 題材

- `bc.aidd-trend-compass` の `docs/`(`develop` 枝、先頭 `eebbe43`。2026-10-15 時点)
- 出典は、このリポジトリでなく、題材の側のパスで示す(`docs/decisions/...` は、題材側の `docs/decisions/...`)

## 質問に付ける札

質問に、2 つの札を付ける。札は、人が付ける。ベクトルから算出するものではない。結果を、種類ごとに集計し、弱点を知るために使う。検索の絞り込みには使わない(検索の絞り込みに使うメタデータは、別に、②の設計で決める)。

| 軸 | 札 | 意味 |
|---|---|---|
| 内容(何を問うか) | 仕様 | 何を、どうするか |
| | 理由 | なぜそう決めたか |
| | 固有名・数値 | 名前、定数、既定値など、語句そのものが答え |
| 難所(何を試すか) | 基本 | 言葉が原文に近く、素直に答えが書かれている |
| | 言い換え | 原文と違う言葉で聞く |
| | 追記が元を覆す | 元の本文と、後の追記が食い違う。現行の仕様は追記 |
| | 横断 | 答えが、複数の文書にまたがる |
| | 要確認の扱い | 資料自身が、「要確認」「記録なし」と述べている |
| | 答えが無い | 資料に、答えが書かれていない |

## 測り方

| 指標 | 見方 |
|---|---|
| 検索の当たり | 質問を検索にかけ、上位 5 件の断片に、出典の文書が入るか。LLM に依らず、分け方・検索方式・埋め込みモデルの比較に使う。問 11 は、出典が無いため、対象外 |
| 答えの正しさ | 期待する答えの要点を満たすか。人が見て、○(満たす)・△(一部)・×(外れ、または作り話)で付ける。問 6・12 は、「要確認」と答えられれば○。問 11 は、「資料に無い」と答えられれば○ |

札ごとに集計し、どの種類の問いで弱いかを見る。
