# plans

プロジェクトの計画書を整理する。計画書の数が増えても、作業中のものを見つけやすくするためのスキル。

## 操作

- `整理`: 完了した計画書を、`archive/<年-月>/` に移す

## 書式

```
/plans 整理
```

- 引数は無い。対象は、実行しているプロジェクト(作業ディレクトリの git リポジトリ。`git rev-parse --show-toplevel` で決める)
- 移す作業は、そのリポジトリの中で行う
- そのリポジトリに `docs/superpowers/plans/` が無いとき(ルートのリポジトリで実行した場合など)は、何もせずに、「ここには計画書の置き場所が無い。プロジェクトのディレクトリで実行してほしい」と報告する

## 置き場所

```
docs/superpowers/plans/                      作業中の計画書(直下の .md)
docs/superpowers/plans/archive/<年-月>/      完了した計画書
```

- `<年-月>` は、ファイル名の先頭の日付(`YYYY-MM-DD-...`)の、年と月。計画書を作った月で決まる
- `archive/` の中は、整理の対象にしない

## 動き(整理)

1. **集める**: 実行しているプロジェクトの `docs/superpowers/plans/` 直下の `.md` を調べる。各ファイルの先頭20行に、`Jira: <エピックのキー>` の行があるものを、整理の対象にする
   - 対象外にするもの: `Jira:` の行が無いもの、ファイル名が `YYYY-MM-DD-` で始まらないもの。触らず、件数とファイル名を報告する
2. **完了の判断**: 対象の計画書ごとに、エピックの状況を Jira で調べる(読み取りと接続は `/jira` スキルのルールに従う)
   - 判断の基準: エピックの子タスクが1件以上あり、そのすべてが完了の状態(`statusCategory = Done`)
   - 子タスクが0件のとき、エピックが見つからないとき、未完了の子タスクがあるときは、完了とみなさない。理由を添えて、報告する
   - エピック自体の状態は、判断に使わない
   - 取得していない情報は「未確認」と書く。推測で完了にしない
3. **一覧を見せる**: 移す計画書について、ファイル名、エピックのキー、子タスクの数(完了/全体)、移動先のパスを示す。移さないものは、理由を添えて、別に示す
4. **確認を取る**: 一覧を見せたあと、了承をもらってから移す。了承が無ければ、何も動かさない
5. **移す**: `mkdir -p` で月のフォルダを作り、`git mv` で移す(履歴を保つため。`mv` は使わない)
   - 移動先に、同名のファイルがあるときは、そのファイルだけ、移さずに報告する
   - 削除はしない
6. **参照の確認**: 移した計画書の旧パスを、そのリポジトリの中で検索する(`docs/`、`CLAUDE.md`、`README` など)。参照が残っていれば、場所を報告する。直すのは、頼まれたときだけ
7. **報告**: 移したもの、移さなかったもの(理由つき)、参照の残りを、簡潔に示す。コミットは、頼まれたときだけ行う

## やらないこと

- 計画書の中身を、書き換えない
- `Jira:` の行が無い計画書を、移さない(Jira に結びつかない計画書は、頼まれたときに、別の作業として行う)
- 作業中の計画書(未完了の子タスクがあるもの)を、移さない
- コミット・push・マージは、頼まれたときだけ
- `.superpowers/` 以下(サブエージェント実行の作業用の記録)は、触らない

## 前提

- 計画書の先頭に `Jira: <エピックのキー>` の行があること。この行は、Jira の指示から計画書を作るとき(`/jira-exec` の、計画を作る流れ)に付ける
- 計画書の置き場所が、`docs/superpowers/plans/`(`superpowers:writing-plans` の既定)であること
